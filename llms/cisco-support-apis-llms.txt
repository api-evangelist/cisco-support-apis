# Cisco Support APIs

> Eight REST APIs that expose Cisco's TAC and support-lifecycle data: end-of-life
> milestones, entitlement and coverage, product information, suggested software,
> defects, TAC cases, software distribution, and RMAs. Available only to Cisco Smart
> Net Total Care (SNTC) customers and Cisco Partner Support Service (PSS) partners.
> Base host https://apix.cisco.com. OAuth 2.0 client credentials only.

This file was generated by API Evangelist from Cisco's public documentation on
2026-08-19. Cisco does not publish an llms.txt for these APIs
(https://developer.cisco.com/llms.txt returns 404). Not affiliated with Cisco.

## Before you call anything

- Auth: POST https://id.cisco.com/oauth2/default/v1/token with
  grant_type=client_credentials, client_id, client_secret. Send the result as
  `Authorization: Bearer <access_token>`. Tokens live 3599 seconds. There are no
  scopes; which APIs an application may call is fixed at registration time.
- Entitlement: an unentitled caller cannot get a working token. Requires an SNTC
  contract (customer) or a PSS contract number (partner), then an application
  registered at https://apiconsole.cisco.com/.
- No sandbox, no test mode, no free tier, no published pricing.
- Status codes lie. Validation errors come back as HTTP 403; "no records found" and
  entitlement warnings come back as HTTP 200; rate-limit exhaustion is 403, never
  429, and there is no Retry-After. Always parse the body code.
- No idempotency mechanism anywhere, including on the POST-only Automated Software
  Distribution API, two of whose operations sign legal agreements.

## APIs

- [EoX](https://developer.cisco.com/docs/support-apis/eox/): end-of-life and
  end-of-support milestones by product ID, serial number, software release string or
  date range. Base https://apix.cisco.com/supporttools/eox/rest/5. Max 20 identifiers
  per request. Page index is a PATH segment.
- [Serial Number to Information](https://developer.cisco.com/docs/support-apis/serial-number-to-information/):
  coverage status, coverage summary, owner status and orderable product identifiers
  for serial numbers or instance numbers. Base https://apix.cisco.com/sn2info/v2.
- [Product Information](https://developer.cisco.com/docs/support-apis/product-information/):
  product attributes and MDF hierarchy IDs by serial number or product ID. Base
  https://apix.cisco.com/product/v1. 500 records per page.
- [Software Suggestion](https://developer.cisco.com/docs/support-apis/software-suggestion/):
  Cisco-recommended releases and images by product ID or MDF ID, plus compatibility
  against a current release. Base https://apix.cisco.com/software/suggestion/v2. Max
  10 IDs (1 for /compatible/).
- [Bug](https://developer.cisco.com/docs/support-apis/bug/): Cisco defect lookup by
  bug ID, product ID, product series, product name, or keyword search. Base
  https://apix.cisco.com/bug/v2.0.
- [Case](https://developer.cisco.com/docs/support-apis/case/): TAC case summary and
  detail by case ID, contract ID, or up to 10 Cisco.com user IDs. Base
  https://apix.cisco.com/case/v3. 100 records per page.
- [Automated Software Distribution](https://developer.cisco.com/docs/support-apis/automated-software-distribution/):
  software metadata, MD5 checksums, signed download URLs, and electronic signature of
  the K9 and EULA agreements. Base https://apix.cisco.com/software/v4.0. POST only.
  25 records per page, max 5 image GUIDs per download.
- [Service Order Return (RMA)](https://developer.cisco.com/docs/support-apis/service-order-return-rma/):
  RMA detail by RMA number, or every RMA for a Cisco.com user in a date range. Base
  https://apix.cisco.com/return/v1.0.

## The identifier graph

serial number -> orderable product ID (SN2INFO) -> MDF ID (Product Information)
-> suggested software (Software Suggestion) -> image GUID -> download URL (ASD).
Coverage summary yields contract IDs, which the Case API accepts. See
data-model/cisco-support-apis-data-model.yml.

## Contracts

- Cisco publishes a WADL file per API and a Swagger YAML for ASD v4.0, linked from
  https://developer.cisco.com/docs/support-apis/cisco-support-apis-wadl-files/, but
  every download returns HTTP 403 without a Cisco API Console sign-in. There is no
  anonymously fetchable OpenAPI.
- First-party Postman collection (BSD-3, last updated 2020):
  https://github.com/CiscoDevNet/Cisco_Support_API_Postman — 33 requests across seven
  of the eight APIs. Its environment still points at the retired api.cisco.com host
  and cloudsso.cisco.com token endpoint.

## No

No MCP server. No A2A agent card. No webhooks, events or AsyncAPI. No GraphQL. No
first-party SDK in any language. No /.well-known/api-catalog. No published
deprecation policy or Sunset headers. The public API changelog page has zero entries.
